What you will learn.

Turn a reusable procedure into a discovered, invocable SKILL.md artifact.

Application labWhat you will learnHow to runArchitecture & workflowCode walkthrough
01

Choose a discovery level

Author a project skill under .claude/skills/security-check/SKILL.md or a personal skill in the private user skills directory. The corresponding setting source controls discovery.

02

Write frontmatter and a workflow body

The app writes a real name, an editable single-line description, optional allowed-tools and trusted Markdown instructions. A specific description tells the model when the workflow is relevant.

03

Compare direct and model invocation

Direct /security-check dispatch loads the skill by name. A natural security-review request lets the model choose the matching Skill workflow. Both paths are observed with actual SDK results.

04

Pre-approve without confusing it with restriction

Compare allowedTools in query options with allowed-tools in SKILL.md. These pre-approve calls; explicit tools and the host target guard enforce the classroom access boundary.

05

Build release-notes from real history

The release exercise creates an owned classroom Git repository with two commits, exports actual git log, and lets /release-notes summarize that JSON. The model does not execute Git or inspect your working repositories.

06

Iterate on the description

Edit the description or select the tuned version, start a fresh session, and inspect the generated SKILL.md and completed calls. One successful invocation is an observation, not a statistical guarantee of trigger quality.
