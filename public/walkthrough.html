01

Authoring surface

Students edit the description, while trusted templates fix the name, workflow and supported frontmatter. This teaches authoring without introducing arbitrary command hooks or dynamic shell substitutions. Full raw skill editing is outside this app.

02

Project and personal levels

Project skills can be committed and shared. Personal skills apply across projects through the user configuration area. This lab uses a private user directory so it does not alter your existing personal skills.

03

Approval is not restriction

allowedTools and skill allowed-tools pre-approve tools. They do not themselves constrain all tool use. The host also supplies an explicit tool list, disallowed tools and target checks. No shell, file edits or external web tool is exposed to the model.

04

Description tuning

A specific description names the task and trigger terms. This lab records one fresh model invocation after tuning, not an evaluation dataset or a statistical proof of improved selection.

05

Release-notes evidence

The host runs fixed Git commands only in a newly created private classroom repository, with per-command identity settings. The skill reads an export from actual git log; it does not inspect the course repository or run a model Bash command.

06

Older commands and collisions

A flat .claude/commands/name.md file is an older command form; skills are the recommended successor. A command-file name can shadow bundled commands/skills. These compatibility and collision cases are reference material, not executed experiments here.
